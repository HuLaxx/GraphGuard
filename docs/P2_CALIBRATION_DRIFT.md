# GraphGuard — P2 offline calibration and shift monitor

**Scope:** research using original synthetic generator only. This report is **not live** and never changes the source ledger, case scores, persisted verdicts or hosted UI. `python -m ml.monitoring.synthetic_calibration_drift --count 720 --seed 42 --output /tmp/graphguard-calibration.json` trains the existing strict point-in-time Logistic/XGBoost baselines, selects the model using **validation PR-AUC**, fits Platt post-calibration using only the validation period, and compares raw and calibrated scores on the same *untouched* chronological test period. It selects respective 5% FPR target thresholds on validation negatives only. The observed test FPR may exceed 5%; the pipeline MUST report it rather than hiding or fixing the threshold based on test labels.

The JSON includes raw vs calibrated held-out PR-AUC, Brier, ECE, precision@K, operating FPR and recall; 150 fixed-seed moving-block *descriptive* PR-AUC resamples with explicit counts; train-versus-test population stability index (PSI) for all 12 point-in-time features and the chosen model's score distribution. PSI handles reference constants as unscorable rather than silently reporting zero drift, and rejects NaNs/undersized windows. PSI is **not** concept drift, causal bias, fairness or evidence of observed real fraud. No alert or retraining is triggered automatically. Entity overlap and zero-new-user cold-start blind spots remain explicitly flagged; fitted validation ECE is optimistic due to in-sample calibration. The model selected before calibration is not changed based on test metrics.

Review `.github/workflows/p2-calibration-drift.yml` for actual CPU-only unit + report acceptance and uploaded data. The pre-existing production-ish `ml/monitoring/drift_detection.py` has a permissive optional-Evidently fallback; this new path is **separate and enforced**, not an unsupported claim that production drift is now monitored. Next production gates are independently licensed datasets, shadow monitoring thresholds, preapproved rollback mechanics, enterprise reviewer auth and cloud deployment approval. **Never use a fraud score as proof of wrongdoing or an automated denial.**
