# P2 routing benchmark — real OR-Tools versus capacity/window-aware baseline

**New on a separate review branch; exact-head CI must pass before claiming verification.** The benchmark uses the existing `VehicleRoutingOptimizer` with real OR-Tools, not simulated routes, compared to a deterministic first-feasible nearest-neighbour planner on the **same original synthetic depot, customer positions, vehicle capacities, 4-minute service times and UTC delivery windows**. Three fixed fixtures include eight stops/one van, twelve stops/two vans, and an intentionally impossible capacity case. Each method is evaluated independently for assignment count, missing stops, time-window/capacity/duplicate violations, straight-line Haversine kilometres, summed route durations, one-run solver execution milliseconds and **illustrative** GBP cost at 0.35 per kilometre. If one method leaves more stops unassigned, its distance/cost must not be compared as a savings estimate.

The optimiser uses straight-line distance and a fixed 30 km/h speed; neither is a verified road-network ETA. Route duration is the planner's internal schedule estimate; no worker wages, fuel consumption, carbon, congestion, demand distribution or customer-facing SLA was measured. The nearest-neighbour planner respects constraints but deliberately performs no backtracking or vehicle reassignment. The infeasible case is explicitly reported as unassigned. A single successful synthetic run cannot establish superiority or production cost savings.

Reproduce from repository root: `cd backend && PYTHONPATH=. python -m src.optimization.benchmark --output /tmp/fleetflow-routes.json`. CI also uses `PYTHONPATH=backend python -m pytest tests/test_routing_benchmark.py` and uploads the exact benchmark JSON. The baseline, inputs, measured results and known limitations are independently reviewable. No paid provider, AWS resource, real GPS journey or production dispatch is invoked by this benchmark.
