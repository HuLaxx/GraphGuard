# P2 — Forecast uncertainty and bounded synthetic benchmark

The historical ridge-log-return AR(1) test report is compared on **the same held-out targets** to last close and trailing mean; no test-period hyperparameter selection occurs. `forecast_quality.py` recomputes per-method MAE, RMSE, median/p95/max absolute error from the actual held-out predictions (it does **not** trust cached summary metrics). It reports a signed paired MAE delta (model minus last-close baseline) and an explicit underperformance flag. The fixed-seed 250-repetition moving-block bootstrap uses consecutive blocks of up to five held-out minutes; its percentiles are *heuristics*, particularly with small sample sizes and serial dependence. This is not calibrated model confidence, a formal performance guarantee or evidence of profitable trading.

`benchmark_forecast_quality.py` builds 3000 deterministic UTC contiguous fixture minutes, with 1500 training observations, 500 validation observations and 1000 held-out test observations, and prints measured elapsed milliseconds and error summaries from the CI runner. The 15-second limit is a deliberately loose **CI regression budget**, not a production latency SLA. Runtime depends on the runner; inspect the JSON attached to the [forecast-evaluation workflow](https://github.com/HuLaxx/Sentinance/actions). Use `cd apps/api && python -m benchmark_forecast_quality` to repeat offline.

For an independently pinned operator-approved report, run `python forecast_quality.py /path/report.json --sha256 PINNED_REPORT_HASH --output unique-quality.json`. Any failed hash, invalid/small report or invalid/NaN predictions fails closed. No real licensed dataset, trading strategy, transaction fees, distributed monitoring or automated drift retraining is asserted. We do not compute trading returns from a next-close regression, since a trading policy would require its own timing, spread/fee/slippage and market-impact assumptions.
